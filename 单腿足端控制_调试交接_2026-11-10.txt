三、上电参考：已实现什么、仍依赖什么

官方方案的核心是人工恢复机械参考姿态，再建立电机读数与实际关节角的对应关系。
编码器在转子端，只保留单圈绝对位置，电机断电丢累计圈数；原始转子上电角0～2π。
本工程反馈已除6.33，不能要求motor[].measure.Pos也在0～6.28，不能重复乘除减速比。
手册：https://techshare.co.jp/faq/wp-content/uploads/2023/12/GO-M8010-6_Motor_User_Manual_V1.0.pdf （第3节）

当前采用用户讨论确定的固定姿态方案：
  人工摆到髋约+60°、相对膝约-120°并对齐机械标记
  -> 上电/主控复位
  -> motor_task_init等待已接入电机合法反馈、检查初始故障
  -> leg_init加载几何、参考关节角和历史参考读数
  -> single_leg_test首次执行时，用motor[0/1].measure.Pos覆盖腿0的start_motor_Alpha/Beta
  -> Get_Now_Pos_Spd(0)按新参考重新计算Joint和Foot
  -> 直接进入Single_Leg_Hold，保持1秒，再自动准备和迈步。

关键约束：
- 采集只在initialized=false时发生一次；正常运动不重采集，不修改编码器原始反馈。
- 每次主控复位也会重新采集，复位前同样必须摆回标记；没有遥控确认或姿态识别等待阶段。
- 软件采集不会确认摆放是否正确。参考角仍为近似手动测量的+60°/-120°，实际不符会造成角度/FK误差。
- 不支持任意姿态断电重启自动寻找机械初始位；固定姿态必须由人工保证。
- 同一姿态上电读数通常接近，但不依赖与历史数值完全相等，当前使用本次参考。
- dog.c历史值0.0717615187/0.38349548 rad仍保留，首次进入测试后被本次采集覆盖，不再追赶它们。
- main.c中“自动归位使用leg_init参考”的旧注释已不代表当前活动流程；以single_leg_test实现为准。
- Leg_Initpos_Reset()仍在main中注释；它要求全8台mode==0，当前两台FOC测试不靠此函数采集。

换算已存在，不另外重复叠加零偏：
  当前关节角 = 方向*(当前电机位置-本次参考电机位置)+参考关节角。
  关节位置目标由Joint_Convert_To_Motor反向换算；足端VMC通过反馈FK/J直接计算力矩。

四、活动入口、阶段与参数

main -> control_task_init（启动TIM8）-> leg_init -> while循环control_task
control_task -> SBUS_Handle -> single_leg_test。
TIM8约1 ms调用motor_task，每次发一台；当前2台轮发，每台约2 ms；测试目标约2 ms更新。
main仍注释start_enter、TIM3启动、motor_test、BMI088_init；GamePad_Control_Obs也注释。
遥控解析虽在运行，single_leg_test没有遥控允许/停止/离线控制，不要套用motor_control_text的开关行为。

阶段枚举仍为Return=0/Hold=1/Prepare=2/Stance=3/Swing=4。
全局初值仍写Return，但首次采集初始化会显式切到Hold，因此正常启动不执行旧回位分支。
旧Return插值、2°/0.1 rad/s连续500 ms到位判断仍留在代码中，此次正常启动绕过它们。
  Hold：软件关节PD保持本次采集位置1秒。
  Prepare：从实测足端用2秒移到参考X+4 cm、参考Z。
  Stance：2秒从前端移到后端，总行程8 cm，Z不变。
  Swing：2秒从后端移到前端，Z=参考Z+0.02*sin²(pi*u)，然后循环。
参数：力矩限幅ID0/1=1.5/2.5 N·m；关节保持Kp=20、Kd=0.4；足端Kp=150 N/m、Kd=5 N·s/m。
内置K_p/K_w=0，command_mode=1，最终力矩经测试限幅后交给Set_Motor_Target_Torque。
return_max_speed=0.3和归位时间计算仍保留，但不决定当前Hold->Prepare的进入条件。
没有重力前馈，实际负载、摩擦、接触反力及PD->VMC切换效果尚待验证。

Single_Leg_Stage枚举
  0 Single_Leg_Return
    采集本次反馈为boot_motor，从此处平滑插值至保存的电机参考读数。
    归位时间=max(4秒，1.5*最大电机角距离/0.3)，三次平滑插值u²(3-2u)。
    软件PD计算两电机力矩，电机内置K_p/K_w置0，command_mode=1。
    插值完成且两电机误差均小于2°、速度绝对值均小于0.1 rad/s，连续500毫秒才进入下一阶段。
    条件未满足就继续归位控制，没有“到时间就强行进入迈步”的分支。
  1 Single_Leg_Hold
    继续软件关节PD保持参考读数1秒。
  2 Single_Leg_Prepare
    保存实测足端为准备起点，用2秒移动到参考X+4厘米、参考Z位置。
    此时切换到足端VMC，归位软件关节PD不再产生输出。
  3 Single_Leg_Stance
    2秒内足端从前端移到后端，Z恒定，端点目标速度为0。
  4 Single_Leg_Swing
    2秒内从后端移到前端，Z额外增加step_height*sin²(pi*u)，端点目标速度为0。
    之后与Stance循环。

步态力矩链
  Get_Now_Pos_Spd(0) -> 当前Joint、Foot.p/v
  -> 生成Foot_Target.p/v
  -> F=150*(目标位置-实际位置)+5*(目标速度-实际速度)
  -> VMC_Jacobi_Matrix()，tau=J^T*F并应用电机方向
  -> 测试入口分别限幅1.5/2.5 N·m
  -> Set_Motor_Target_Torque()写motor[0/1].target.T
  -> TIM8发送

此处VMC使用虚拟足端力，没有足端力传感器或实测接触力闭环，也未实现重力前馈补偿。
当前测试直接用Foot.v做阻尼，区别于旧PD_Control()中未除采样周期的误差差分D项。
Set_Motor_Target_Torque()会将target.Pos/W写成反馈，内置PD为0时控制作用来自target.T。
leg[0].Pctrl.Motor_Target仅在归位/保持分支更新，步态时其Beta保持旧值属于当前实现行为。
观察膝实际运动应看motor[1].measure.Pos和Joint.Pos.Beta，步态目标看Foot_Target。

五、遇到的问题、证据及尚未解决部分

A. 归位有时只向内弯曲，电机重上电与只复位主控的现象不同

用户多次反馈，不管腿的初始位置怎样，上电只向内弯一次并保持。
曾反馈复位不明显、只有重新上电才动，并确认测试从其他机械姿态上电。

厂家GO-M8010-6手册第3节说明：编码器位于转子端，是单圈绝对编码器。
电机运行中累计转子圈数，电机掉电后累计圈数丢失，上电首先给出转子单圈位置。
当前程序将反馈帧第7～10字节组合成int32位置N，计算
  motor.measure.Pos = N * 2*pi / (32768*6.33)
当前接收链未减去本次上电位置，零点也不会自动成为当前关节姿态。
转子一圈折合输出轴2*pi/6.33≈0.992604 rad≈56.872°。
不同机械位置相差这一量时，重新上电的反馈可能相同，固定旧读数不能唯一确定输出轴机械位置。
参考来源（厂家编写的手册镜像，第4～5页）
  https://techshare.co.jp/faq/wp-content/uploads/2023/12/GO-M8010-6_Motor_User_Manual_V1.0.pdf

前面助手直接用旧读数实现“任意姿态上电归位”，遗漏了跨电机断电的圈数确认，这个实现前提有缺口。
调整归位PD只能处理读数误差，不恢复机械参考，不能宣称任意姿态自动回零已修复。
仍需通过实物已知姿态或其他机械基准确认真实角度，厂家原理也不能单独证明每次不动都由圈数造成。
dog.c中“上电编码器值就是0”“输出轴一圈九个绝对位置”等是旧注释，不适用于此处8010解释。

已讨论但尚未实施的解决流程
  上电零力矩 -> 手摆已知姿态 -> 遥控确认 -> 记录本次ID0/1参考 -> 保持 -> 迈步。
没有新增等待标定状态，没有接遥控确认，没有完成该方案。
真正从任意姿态自动归位，需要能消除位置歧义的机械原点、输出轴角度反馈或其他可靠位姿基准。
没有授权或实施撞限位寻零，不自行假定实物有合适的原点开关/机械止挡。

- L1=0.250 m：髋轴到膝轴；L2=0.247 m：膝轴到足端球心。
- 足端球半径0.020 m，不把L2改为0.267 m。
- 膝同步带28:28、非交叉、1:1；不要重复套用电机内置减速比。
- 髋固定机身，大腿带着膝电机外壳一起运动。
- X向前、Z向上，髋轴为腿坐标原点；单腿只控制X-Z平面。
- q1/Alpha：大腿竖直向下为0，向前为正，范围[-60,+60]°。
- q2/Beta：小腿相对大腿的有符号角，伸直为0，与q1采用同一旋转正向，范围[-150,+30]°。
- 小腿相对机身角是q1+q2。膝反馈已经是相对自身外壳的转角，不再额外减髋角。
- 内部单位：rad、rad/s、m、N、输出轴N·m；IMU欧拉角接口为度。

五、现有单腿数学与输出接口

反馈链：
  motor[].measure
  -> Get_Now_Pos_Spd(0)
  -> Motor_Convert_To_Joint()
  -> Kinematic_Solution()
  -> leg[0].Joint、Foot.p、Foot.v

已有串联正解：
  x=L1*sin(q1)+L2*sin(q1+q2)
  z=-L1*cos(q1)-L2*cos(q1+q2)
  v=J*dq

已有VMC_Jacobi_Matrix()：
  tau_joint=J^T*F
  再各乘motor_Alpha_dir/motor_Beta_dir，转换成电机正向；方向只处理一次。
  J转置不需要求逆，不能把伸直时的问题说成此乘法会除零；初测仍避开伸直姿态。

Set_Motor_Target_Torque()：
- 将leg.Motor_Torque写入两个motor.target.T，同时把target.Pos/W写成对应反馈。
- 自身不清内置K_p/K_w，测试入口必须明确把两者置0。
- 当前只有±33.5 N·m通用限幅，不适合作为单腿初测限幅。
- 可在独立测试中先对Motor_Torque分别低限幅，再调用此函数，避免为了初测广泛修改旧动作。

Set_Motor_Target_Pos()：
- 写IK得到的目标位置/速度，并把target.T清零。
- 当前是位控路径，不是已接好的“位置PD+非零前馈力矩”混控流程。

motor_YS_Data_send()已有换算：
  T_rotor=target.T/6.33
  Kp_rotor=K_p/(6.33^2)
  Kd_rotor=K_w/(6.33^2)
  位置/速度的减速比换算已在底层完成，上层不能再重复换算。
负数协议打包已经修复，勿恢复负浮点直接转无符号整数的旧写法。

十、力位混合相关结论

- 电机接口已具备target.Pos/W/T和K_p/K_w，支持同时发送。
- 关节混控关系：tau=Tff+K_p*(qd-q)+K_w*(dqd-dq)，仍是command_mode=1的FOC。
- 当前上层主要是位控和力控分支，没有接好独立的关节混控流程。
- Pos_motor.Tfb为保留字段，Set_All_Motor_Param只设增益，不把Tfb叠加到target.T。
- 以后可用混控叠加重力补偿；这时需要运动部件质量、质心与重力方向，快速运动补偿才进一步需要惯量/加速度。
- 初步混控不必须新增传感器；精确实测足端力闭环才需要力测量或可靠估计。
- 启用内置PD后，仅限制target.T不能限制三项相加的总力矩，不能直接沿用纯力矩测试的限幅结论。
- “关节位置PD叠加力矩”与“足端X控位置、Z控接触力”是不同层次的方案。
- motor_task.h第30行附近已补各模式参数和范围注释。约±810 N·m等是协议表示范围，不是实物输出能力；厂家公布最大输出23.7 N·m、最高速度30 rad/s（24V），不是持续同时工作点。
