二、机构、坐标和单位（最新有效约定）
============================================================

机构：串联髋膝两自由度腿，无主动侧摆。
- 髋电机外壳固定机身，输出连接大腿。
- 膝电机外壳随大腿运动，通过非交叉 28 齿对 28 齿同步带驱动小腿，机械传动比 1:1。
- L1=0.250 m：髋轴到膝轴；L2=0.247 m：膝轴到足端球心。
- 足端球半径记录为 0.020 m；运动学末端取球心，不直接把 L2 改成 0.267 m。

坐标：机身 X 向前、Y 向左、Z 向上；单腿髋轴为原点，计算 X-Z 平面。
- q1/Joint.Pos.Alpha：大腿竖直向下为零，向前为正，范围 [-60,+60]°。
- q2/Joint.Pos.Beta：小腿相对大腿的有符号转角，同向伸直为零，与 q1 同旋转正方向；范围 [-150,+30]°。
- 小腿相对机身的角度为 q1+q2；不能把 q2 当膝内夹角，也不能额外减去 q1。
- 电机输出轴相对自身外壳的读数已是相对角；膝电机外壳跟随大腿，不需要软件再次扣髋角。
- 上述是数学正向；实际 motor_Alpha_dir/motor_Beta_dir 各取 +1 或 -1，装配后验证。
- 四腿编号与前左/前右/后左/后右尚未确定，不猜测原机镜像映射。

内部单位：位置 rad，速度 rad/s，长度 m，足端力 N，输出轴力矩 N·m。
IMU 欧拉角接口为度，进入三角函数时转换；交流时可用度。
电机内部减速比 6.33 和同步带 1:1 是不同层级，不能重复换算。

上层均为减速器输出轴端口：
  g = 6.33
  T_rotor = motor.target.T / g
  Kp_rotor = motor.K_p / g^2
  Kd_rotor = motor.K_w / g^2

- motor[].command_mode 是要发送的模式；motor[].mode 是接收到的实际模式。
- 当前 command_mode=1 发送 FOC 使能，0 对应驱动锁定/禁用模式；不能沿用 A1 的 mode=10 判定。
- feedback_valid 表示曾收到合法反馈，不等于持续新鲜、控制闭环已运行或已验证全部八台。

3. 三种“KD”必须明确名字，不能混用。
A. 旧速度测试中的 test_kd：转子端协议增益。
B. motor[id].K_w：统一接口的输出轴速度增益。
C. 当前 motor_test() 的 hold_kd：软件 PD 中乘反馈速度的输出轴阻尼系数。
关系：K_w = test_kd * 6.33^2；发协议前再除 6.33^2。
当前软件 hold_kd=0.2，而 motor[id].K_w=0，所以协议内置 Kd=0；不是没有软件阻尼。

用户曾说“之前 kd=0.4 能动”，交接不得直接当成已核实的协议数值。
当时核对的回退源码 test_kd=0.04。若用户后续确改为0.4，先问清是哪一个变量。
理想静止起步、速度目标0.5 rad/s、前馈力矩0时，按当前代码模型：
  输出力矩 ≈ K_w * 0.5 = test_kd * 6.33^2 * 0.5
  test_kd=0.04 -> 约0.80 N·m；test_kd=0.4 -> 约8.01 N·m。
  若只是 K_w=0.4 -> 约0.20 N·m，不能套用8.01的结论。
这些是基于误差的理想计算，不是实际测得的机械输出；实际还受限幅、量化和负载影响。

八、当前串联数学及数据链路
============================================================

已在 dog.c 实现：
- Kinematic_Solution：串联正解、J*dq，rod[0]=0.250、rod[1]=0.247。
- Kinematic_Inversion_Update：串联位置逆解、双分支及关节范围筛选。
- Kinematic_Inversion_Try：位置+速度逆解，成功才更新Joint；失败保留原值。
- Kinematic_Inversion：兼容原void接口，调用Try，不把失败当成有效新目标。
- Joint_Convert_To_Motor / Motor_Convert_To_Joint：参考角和方向的正反转换。
- Motor_Convert_To_Foot / Foot_Convert_To_Motor：组织反馈与目标转换链。
- VMC_Jacobi_Matrix：串联J转置映射，随后各关节乘安装方向，符号只处理一次。
- 旧并联公式有注释保留供对照，不要误把注释代码当成当前活动实现。
- Get_Now_Pos_Spd中旧“正解后又逆解回写反馈角”的调用已注释；不会用目标分支覆盖实测角。

公式：
  x=L1*sin(q1)+L2*sin(q1+q2)
  z=-L1*cos(q1)-L2*cos(q1+q2)
  J=[L1*cos(q1)+L2*cos(q1+q2), L2*cos(q1+q2);
     L1*sin(q1)+L2*sin(q1+q2), L2*sin(q1+q2)]
  v=J*dq；tau_joint=J^T*F；det(J)=L1*L2*sin(q2)

逆解现状：
- q1范围[-pi/3,+pi/3]，q2范围[-5pi/6,+pi/6]。
- 只吸收少量浮点舍入超界，不将不可达目标任意投影成边界目标。
- 参考膝角非零时保持同符号分支，当前支无合法解则失败，不自动翻到另一支；零参考可择合法支。
- 有非零足端速度时，|sin(q2)|<=0.001会拒绝速度求逆；足端速度为零可接受合法位置解。
- Foot_Convert_To_Motor首次以当前反馈关节角选支，之后沿用上次成功目标；失败不更新目标。
- position_target_initialized[4] 是static，初始全false；Set_Motor_Target_Torque会清对应腿标志，供下次位控重新选支。
- J^T本身在伸直姿态仍可算，奇异性影响独立运动能力和速度逆解，不要说所有力控乘法都会除零。

坐标变换/轨迹速度：
- Coordinate_Transform已由旧Pitch*0.1217改为度转弧度，并配套旋转方向。
  Follow_Ground：x'=x*cos(theta)-z*sin(theta)，z'=x*sin(theta)+z*cos(theta)。
  Follow_Dog直接沿用腿/机身坐标；单腿初测优先明确采用这一模式。
- Line_Pos已补目标速度并做同一坐标旋转；其他位控轨迹逐一看源码，不能宣称全部速度前馈补齐。
- 用户明确暂不补俯仰变化产生的角速度速度项，不擅自追加。
- 轨迹生成器可复用插值思想，但旧点位、Z符号、范围、增益和镜像仍需适配。

两种控制链不要混淆：
A. 反馈：motor[].measure -> Motor_Convert_To_Joint -> Kinematic_Solution -> leg[].Foot.p/v。
B. 足端位控：轨迹p/v -> Foot_Convert_To_Motor（IK+标定变换）-> target.Pos/W。
C. 足端力控：目标p与反馈p -> PD_Control -> F -> VMC_Jacobi_Matrix -> Set_Motor_Target_Torque -> target.T。
   C无需先算目标逆解；不能因为迁移过IK就强行把IK插进足端力控。
