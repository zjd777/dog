六、电机输出角与髋膝角：已知关系和待标定项
============================================================

theta1/theta2 的定义：电机减速器输出轴相对各自外壳的角度，已换算到输出端。

在本机构的直接髋传动和 1:1 膝同步带条件下：
  q1 = q1_ref + s1 * (theta1 - theta1_ref)
  q2 = q2_ref + s2 * (theta2 - theta2_ref)
  dq1 = s1 * dtheta1
  dq2 = s2 * dtheta2
  s1、s2 各为 +1 或 -1，根据实际安装和反馈方向标定。

重要：
- 计算相对膝角 q2 时，不额外减去 q1。膝电机外壳本身跟随大腿运动。
- 1:1 同步带传动比与电机内部 6.33 减速比是两件事，不得重复计算。
- 数学零位不等于电机回传值为零。
- 可以在任意已知 q_ref 的参考姿态标定 theta_ref，不必把腿摆到伸直或竖直零位。

当前未知但不阻塞纯软件工作的项目：
- theta1_ref、theta2_ref。
- s1、s2 在每条实际腿上的取值。
- 每条腿对应的串口与电机 ID。

软件阶段处理原则：
- 可以使用集中、明确标注的占位配置；不能写成“实机已标定值”。
- 逻辑数组下标不等于通信 ID。
- 八个逻辑数据槽可以先预留；未连接槽位的默认零值不等于有效反馈。
- 不要求用户现在回答当前 ID 0 属于髋还是膝；用户尚未分配位置。

七、串联模型数学依据（由已确认约定推导，尚未写入源码）
============================================================

以下公式可用于实现和审查，不要误认为当前 dog.c 已经采用它们。
设 q12=q1+q2，末端是足端球心。

正运动学：
  x = L1*sin(q1) + L2*sin(q12)
  z = -L1*cos(q1) - L2*cos(q12)

雅可比：
  J = [ L1*cos(q1)+L2*cos(q12),  L2*cos(q12) ]
      [ L1*sin(q1)+L2*sin(q12),  L2*sin(q12) ]
  [vx, vz]^T = J * [dq1, dq2]^T
  det(J) = L1*L2*sin(q2)

位置逆解：
  D = (x*x + z*z - L1*L1 - L2*L2) / (2*L1*L2)
  q2 = atan2( ±sqrt(1-D*D), D )
  q1 = atan2(x, -z) - atan2(L2*sin(q2), L1+L2*cos(q2))
  必须结合髋膝限位和当前/参考姿态选择合法分支。
  暂定膝范围含正负两支，不能一律强制使用 acos 返回的非负膝角。
  速度逆解在 J 可逆时由 J*dq=v 求得。

VMC：
  足端目标误差/速度误差 -> 虚拟力 F -> tau_joint = J^T * F。
  力、位置、速度、J 必须处于相同的坐标定义下。
  从关节力矩转到电机输出力矩时，方向符号和传动比只能在明确位置应用一次。
  若使用期望地面反力，则须明确其与模型足端力的作用/反作用关系，不混用符号。

奇异姿态：
- q2=0 时 J 退化；数学零位仍可定义为伸直。
- J^T*F 本身仍可计算有限力矩，不能说伸直一定导致该乘法除零。
- 但两方向独立运动能力退化，速度逆解在此不可直接求逆。
- 这是串联两连杆的实际几何性质，处理目标工作区和逆解时需考虑；不要为此增加无关并发封装。

工作区和站立示例：
  r = sqrt(L1^2 + L2^2 + 2*L1*L2*cos(q2))，r 是髋轴到球心距离，不是所有姿态下的离地高度。
  q2=0°：r=497.000 mm。
  q2=-60°：r≈430.417 mm。
  q2=+80°：r≈380.729 mm。
  在当前膝范围内 r 约为 380.729～497.000 mm，但这不代表该圆环内所有点都满足髋角限制。
  对正负膝分支，还要结合各自范围及髋角判断可达性。

曾绘制的参考站立姿态：
  q1≈-22.3567°，q2=+45°，足端球心恰在髋轴正下方。
  球心相对髋轴 z≈-0.4591696 m。
  此姿态仅作角度解释示例，不是用户最终确定的站姿或优化结果。
  生成图片只是示意，数值以数学计算和机械模型为准，不能从图片量取尺寸。

验证建议：
- 使用真实正逆解实现做 round-trip，检查 FK(IK(p)) 的末端误差及分支连续性。
- 用真实 FK 的有限差分检查解析 J。
- 检查 F·v 与 tau·dq 的虚功/功率一致性。
- 检查电机角与关节角的正反转换一致性。
- 对工作区外目标、接近奇异姿态及范围边界，明确入口处理方式；不要静默改成无意义目标。
- 不把算法复制到测试里；不依赖真实电机才能验证数学模型。

  Struct_send_motor_YS：Angle、Pos、T、W、Kp、Kd、T_ff。
现有反馈数据：
  Struct_recv_motor_YS：MError、mode、Now_Pos、Now_Angle、Now_W、Now_T、Now_Temperature。

已经核实的源码换算：
- Gearbox_Rate=6.33。
- 发送 W 按 W*128*6.33/pi 编码。
- 发送 Pos 按 (Pos+init_Pos)*32768*6.33/(2*pi) 编码。
- 接收 Now_W 按 raw*2*pi/(256*6.33) 计算。
- 接收 Now_Pos 按 raw*2*pi/(32768*6.33) 计算。
- Now_Angle 是由 Now_Pos 换成度；上层运动学优先使用弧度接口。
- 发送 T 当前是 T*256，接收 Now_T 当前是 raw/256，未见力矩减速比换算。
- 发送 Kp/Kd 当前均按 *1280 量化；实际物理含义、端口归属必须对照官方协议。

必须核对，不能自行当作已知的事项：
1. T/Now_T 属于转子端、减速器输出端还是其他协议定义；如何与模型关节力矩统一。
2. Kp/Kd 的单位、端口和减速比关系；原 A1 的 kp/kw 数值不能直接照抄。
3. 允许的电流、力矩、速度、位置和增益范围；±33.5 只是旧 A1 限制。
4. 原 A1 的 mode 0/10 与 8010 状态字段不是默认一一对应。
5. 当前 UART_recv 将模式写入类成员 mode，而 Get_mode() 返回 recv.mode；
   本轮未找到该解析函数给 recv.mode 赋值，需要在适配时解决字段来源不一致问题。
6. 发送量化变量 YS_T/YS_W/YS_Angle_Pos 当前使用 uint32_t，而新目标允许负值。
   应按官方协议检查有符号量的转换与打包，不能依赖负浮点转无符号后偶然保留低字节。
7. zero() 当前只是令 Pos=recv.Now_Pos（或 Angle=recv.Now_Angle），不是机械关节标定，
   也没有在该函数中设置 init_Pos 为反馈零偏，不要被函数名误导。
8. T_ff 目前没有在 motor_YS_Data_send() 中传递，不能宣称该独立字段已生效。
9. 驱动收发缓冲当前为全局单套 17/16 字节。将来真正扩展多电机时再结合串口/DMA拓扑核对，
   当前不要为未实施的多路通信提前加锁、队列或复杂并发框架。

重要现有测试入口：
- control_task() 每次调用 motor_control_text()。
- motor_control_text() 把 Kp=0、Kd=0.01、T=0，并在 SBUS 在线时写 W=1 rad/s，离线时 W=0。
- 接入动作目标后，该测试入口若继续写同一目标会覆盖动作输出，必须明确控制来源。
- 当前未接实物，不要求为此现在做实机标定；后续实物运行前需要处理实际测试行为。

dog.c/.h 目前仍是原闭链模型，没有完成串联模型迁移：
- Kinematic_Solution()：必须改为串联正解和 J*dq。

读反馈 -> 电机转关节 -> 正解 -> 力控分支再调用 Kinematic_Inversion_Update() 改写 Joint。
串联迁移时需要整理这条链路，不让目标逆解覆盖实测关节状态。

旧参数及已观察到的具体问题：
- leg_init() 的 rod[]={0.175,0.3,0.175,0.3}、旧初始角、旧编码器零位全部属于原机。
- 原 start_Alpha/Beta 不是用户的髋膝零位：腿0/1为 -116.41°/-203.01°，腿2/3为 23.01°/-63.59°。

- Coordinate_Transform() 使用 Pitch*0.1217f，不是普通度转弧度系数；是否为原机经验补偿需审查。
- PD_Control() 使用相邻误差差分，没有显式除以 dt，原 Kd 和滤波参数与周期相关。
- Judge_Keep_State() 中名为 D0z/D1z/D2z/D3z 的检查实际使用 Foot.p.x，疑似坐标使用错误。
- 原 Kinematic_Solution 根号为 A*A-B*B-C*C，而其他类似位置是 A*A+B*B-C*C；
  不以这些原公式作为新串联实现的正确性基准。

状态机已有语义：
- change_able：允许退出当前状态，不是电机使能。
- execute_able：存在待切换请求，不是 run 的执行开关。
- ChangeDogState 只登记请求，DogFSM 得到许可后执行 exit -> 切换 -> enter -> run。
- 切换当次就执行新状态 run。未切换时也执行当前 run。
- 新请求覆盖旧待处理请求；请求当前状态不会重启，也不会取消另一待处理请求。
- 初始指针指向 Start，但启动时不自动调用 start_enter（当前为空）。
- 尚未实现的弱空回调可能导致切入后不再开放 change_able；只启用已有动作时再处理入口范围。
- fsm.h 当前没有 extern "C" 包装，后续从 C++ 调用时需要处理 C 链接。
