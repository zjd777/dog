阅读约定
  1. 下方按当前源码整理，区分已经连接到入口的调用与尚未连接的动作模块。
  2. 调用树中同一层的项目，除标明互斥分支外，按实际执行顺序从上到下排列。
  3. “每条腿”表示依次处理腿 0、1、2、3；不会同时执行力控和位控两条分支。
  4. 业务函数展开内部调用；HAL、CMSIS、数学库和 CRC 工具只保留接口名称。
  5. 函数定义、头文件声明、状态表登记，都不等于已经连接到运行入口。
  6. 这是一份源码调用关系说明，没有在本次整理中修改控制代码或进行硬件验证。

一、先认识程序的三种执行位置

  主流程：从 main() 开始，初始化后反复执行 while (1)。
  定时器中断：定时到达后调用回调；处理完会返回被中断的位置。
  接收中断：串口或 DMA 收到数据后调用接收回调，更新缓存后返回。

  因此不存在一条“main -> 动作 -> 电机 -> 整个程序结束”的直线流程。
  动作控制每周期计算一次，通信任务周期发送，接收回调独立更新反馈。

五、动作状态机如何分发：模块已存在，当前周期入口尚未连接

  外部业务调用 ChangeDogState(目标状态)
  └─ 记录 next_state，置 execute_able = ENABLE；此时不调用动作

  当前动作调用 SetDogChangeAble(ENABLE/DISABLE)
  └─ 修改当前状态的退出许可 change_able

  外部周期调用 DogFSM()                    my/fsm.c
  ├─ 允许退出、有切换请求、目标不同于当前：
  │  ├─ pCurrentState->exit()                调用旧状态退出函数
  │  ├─ pCurrentState 指向 StateMap[目标状态]
  │  ├─ 更新 last/now/next_state，关闭新状态切换许可并清请求
  │  ├─ pCurrentState->enter()               调用新状态进入函数一次
  │  └─ pCurrentState->run()                 立即执行新状态的一次运行计算
  └─ 条件不满足：
     └─ pCurrentState->run()                 继续执行当前状态的一次运行计算

  请求和许可可以先后到达，判断时同时满足即可。
  初始化指针指向 Start 不会自动调用 start_enter()。
  run() 每次被调用只执行一轮；周期来自外部调度，不是 run() 自己循环。
  GetNowDogState()/GetNextDogState()/GetLastDogState() 只返回状态记录。
  GetDogWhetherChangeAble()/GetDogWhetherExecuteAble() 只返回标志。

六、所有动作共用的当前状态计算：先读反馈，再算足端

  Get_Now_Pos_Spd(legid)                     my/dog.c
  ├─ 从旧 motor[].measure.Pos/W 复制到 leg[legid].Motor
  ├─ Motor_Convert_To_Joint()
  │  └─ 根据旋转方向、参考电机角、参考关节角换算，写入 leg[].Joint
  ├─ Kinematic_Solution()
  │  └─ 根据关节状态与杆长计算，写入 leg[].Foot.p/v
  ├─ Get_Now_Ctrl_State()
  └─ 若为 Force_Ctrl：Kinematic_Inversion_Update()
     └─ 原模型再次根据足端位置更新 Joint.Pos，属于迁移时需重审的旧处理

  输入：缓存电机反馈、腿参数、控制模式。
  输出：leg[].Motor、Joint、Foot，以及原逆解连续角的中间状态。
  它不会主动向电机发查询命令；当前位置来自反馈缓存和模型计算。
  旧数组对应：腿 0 的 Alpha/Beta 为 1/0，腿 1 为 3/2，腿 2 为 5/4，腿 3 为 7/6。
  这些是旧软件映射，不代表新机器人总线 ID 或髋膝安装位置。

七、共用力控调用树：从一个足端目标到两个力矩目标

  line() / Cycloid() / Bezier() / Bezier_Stance()    my/dog.c
  ├─ Get_Now_Pos_Spd(legid)                   展开见第六部分
  ├─ 对应的轨迹生成器，返回当前时刻的 Point：
  │  ├─ line() -> line_Generator()
  │  ├─ Cycloid() -> Cycloid_Generator()
  │  └─ Bezier()/Bezier_Stance() -> Bezier_Generator()
  ├─ Coordinate_Transform()
  │  └─ 写入 leg[].Foot_Target.p；是否用 Pitch 旋转由 pitch_ctrl_state 决定
  ├─ PD_Control()
  │  └─ 足端目标、当前足端、PD 参数和历史误差 -> leg[].VMC_Output_Force
  ├─ VMC_Jacobi_Matrix()
  │  └─ 虚拟力、当前关节角、几何参数 -> leg[].Motor_Torque
  └─ Set_Motor_Target_Torque()
     ├─ 按原代码将 Alpha/Beta 力矩限制到 -33.5～+33.5
     ├─ 写入对应 motor[].target.T
     └─ target.Pos/W 取最近反馈 measure.Pos/W

  这一轮控制计算到“写入 motor[].target”就返回，不会在此处发送串口数据。
  虚拟力来自 PD 计算；当前没有足端测力数据进入这条链路。
  当前正解、逆解和雅可比均为原并联腿模型，不能视为串联腿已适配。
  VMC_Filter() 的调用均已注释，不在上述执行链路中。

  轨迹生成器内部：
    line_Generator()：按时间比例计算直线目标点，无其他业务函数调用。
    Cycloid_Generator()：按时间比例计算摆线目标点，使用数学库 sinf/cosf。
    Bezier_Generator()
    ├─ Bezier_Trans()                        转换起点坐标
    ├─ Bezier_Trans()                        转换终点坐标
    ├─ 计算当前时间比例和贝塞尔曲线坐标
    └─ Bezier_Trans_Inv()                    转回腿坐标，返回目标 Point

八、共用位控调用树：从足端目标到两个位置、速度目标

  line_Pos()/Cycloid_Pos()/Bezier_Pos()/Bezier_Stance_Pos()    my/pos_ctrl.c
  ├─ Get_Now_Pos_Spd(legid)
  ├─ 将上一轮 Foot_Target.p 保存到 Pctrl.Foot_Last_Target.p
  ├─ 对应轨迹生成器：line_Generator/Cycloid_Generator/Bezier_Generator
  ├─ Coordinate_Transform()                  写入 Foot_Target.p
  ├─ Foot_Convert_To_Motor()                 my/dog.c
  │  ├─ Kinematic_Inversion()
  │  │  ├─ Kinematic_Inversion_Update()      足端位置 -> 原模型关节目标角度
  │  │  └─ 继续计算关节目标角速度
  │  └─ Joint_Convert_To_Motor()             方向和参考角转换 -> 电机目标

  本分支没有调用 PD_Control() 和 VMC_Jacobi_Matrix()。
  写入的是原 motor[] 的位置、速度目标，通信发送仍由另一执行路径完成。

十三、时间和姿态两条辅助链路

  13.1 动作时间

  各状态 enter()/run()
  └─ GetTick()                              my/delay_DWT.c
     └─ Generate_Time_Points()
        ├─ DWT_Init()                       首次启动计数，后续不清零
        ├─ CPU_TS_TmrRd()                   读取内核周期计数
        └─ 统计回绕，换算并更新 Time_Points_Param.Now_Tick，单位秒

  动作 t = Now_Tick - tick_start；行走再按 term 对 t 取余。
  HAL_GetTick() 是毫秒节拍，用于电机初始化和 SBUS 超时，不能直接与动作秒数混用。
  Delay_ms 宏 -> Delay_us() -> DWT_Init()、反复 CPU_TS_TmrRd() 忙等待。
  本次检查的 build_support/sources.mk 尚未加入 my/delay_DWT.c。

  13.2 姿态

  当前已连接：main() -> BMI088_init()，配置传感器。

  周期读取与解算尚未在主循环/定时器连接，下列是各接口应衔接的数据顺序：
    BMI088_read(gyro, accel, &temperature)
      -> gyro/accel 采样数据
      -> imu_data_process(gyro, accel, dt_s)
         ├─ normalize_sample()              入口校验和加速度方向归一化
         ├─ 首次：initialize_attitude()
         ├─ 后续：integrate_attitude()
         └─ update_angles()                 更新 imu_angle[]
      -> Euler_Update(&Euler_Angle)          将缓存姿态发布给动作层
      -> Coordinate_Transform()/Yaw_Pos_Crol() 等使用姿态

  上面箭头表示需要连接的数据步骤，不表示 BMI088_read() 内部已经调用姿态解算。
  Euler_Update() 仅复制缓存，不读取 BMI088，也不执行四元数积分。
  get_imu_angle() 直接返回缓存；Yaw_Reset() 保存航向参考并清控制层偏航值。
  gyro 使用 rad/s、accel 使用 m/s²、dt_s 使用秒，发布的 Euler 角使用度。

十六、与原 Corgi 工程的调度对应

十七、最常用的三条阅读路径

  站立力控：
    DogFSM -> stand_enter（进入一次）
           -> stand_run -> GetTick -> Stand_Up
              -> Launch 时记录起点
              -> 后续 line -> Get_Now_Pos_Spd -> line_Generator
                 -> Coordinate_Transform -> PD_Control
                 -> VMC_Jacobi_Matrix -> Set_Motor_Target_Torque
                 -> 写旧 motor[].target，逐层返回

  行走力控：
    DogFSM -> walk_enter（进入一次）
           -> walk_run -> GetTick -> Walk_Away
              -> 换相时更新起点与步长
              -> gait(0～3) -> Bezier / Bezier_Stance
                 -> Get_Now_Pos_Spd -> Bezier_Generator
                 -> Coordinate_Transform -> PD_Control
                 -> VMC_Jacobi_Matrix -> Set_Motor_Target_Torque
                 -> 写旧 motor[].target，逐层返回

  行走位控：
    DogFSM -> walk_enter（进入一次）
           -> walk_run -> GetTick -> Walk_Away_Posctrl
              -> gait_posctrl(0～3) -> Bezier_Pos / Bezier_Stance_Pos
                 -> Get_Now_Pos_Spd -> Bezier_Generator -> Coordinate_Transform
                 -> Foot_Convert_To_Motor
                    -> Kinematic_Inversion -> Kinematic_Inversion_Update
                    -> Joint_Convert_To_Motor
                 -> Set_Motor_Target_Pos -> 写旧 motor[].target，逐层返回

  不需要把 sinf、cosf、sqrtf、atan2f 等当成新的业务层；
  它们是运动学与轨迹计算使用的数学库函数。
